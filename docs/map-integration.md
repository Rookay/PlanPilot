# 地图接口接入

PlanPilot 已内置与业务解耦的地图接口层，当前实现高德地图 Web 服务适配器。未配置 Key 时不会发起地图请求，任务、日程、天气和对话等其它功能不受影响。

## 配置

在项目根目录的 `config.json` 中加入：

```json
{
  "external": {
    "maps": {
      "provider": "amap",
      "base_url": "https://restapi.amap.com",
      "api_key": "你的高德 Web 服务 Key",
      "timeout": 10,
      "default_city": "南京",
      "js_api_key": "你的高德 Web 端 JS API Key",
      "js_security_code": "你的安全密钥"
    }
  }
}
```

也可以用环境变量覆盖：`MAPS_PROVIDER`、`MAPS_BASE_URL`、`MAPS_API_KEY`、`MAPS_TIMEOUT`、`MAPS_DEFAULT_CITY`、`MAPS_JS_API_KEY`、`MAPS_JS_SECURITY_CODE`。配置文件已被 Git 忽略，不会提交密钥。`api_key` 用于后端路线查询；`js_api_key` 和 `js_security_code` 用于浏览器地图展示。

## HTTP 接口

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/maps/status` | 查看是否已配置以及可用能力 |
| GET | `/api/maps/client-config` | 获取地图展示配置，不返回 Web 服务 Key |
| GET | `/api/maps/places?q=人民广场&city=上海&limit=5` | 搜索地点候选 |
| POST | `/api/maps/geocode` | 把地址解析为标准地址和坐标 |
| POST | `/api/maps/routes` | 查询步行、驾车或公交路线 |

常用地点独立保存在本地数据库中，不需要地图 Key：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/locations` | 获取全部常用地点 |
| POST | `/api/locations` | 保存名称、地址和精确坐标 |
| PUT | `/api/locations/{id}` | 编辑地点或设为默认出发点 |
| DELETE | `/api/locations/{id}` | 删除地点 |
| GET | `/api/itineraries/day?date=2026-09-18&mode=transit` | 聚合当天时间轴、地点、路线和通勤警告；可用 `include_return=true` 添加返程 |

第一条常用地点会自动成为默认出发点。切换或删除默认地点时，系统会保证剩余地点中仍然只有一个默认项。

地址解析请求：

```json
{
  "address": "上海市黄浦区人民大道200号",
  "city": "上海"
}
```

路线请求：

```json
{
  "origin": {"longitude": 121.475, "latitude": 31.238},
  "destination": {"longitude": 121.499, "latitude": 31.239},
  "mode": "transit",
  "city": "上海"
}
```

`mode` 支持 `walking`、`driving` 和 `transit`。返回值已经归一化为统一的坐标、米和分钟，不包含高德特有的数据结构。

## 一日行程地图

任务和固定事件可以绑定一个常用地点。行程接口按用户时区筛选指定日期，将默认地点作为出发点，并在相邻事项都有精确地点时计算路线。返回结果包含：

- 当天固定事件、已确认日程和待确认日程；
- 每一段路线的距离、耗时和绘制坐标；
- 第一项的建议出发时间；
- 相邻事项之间通勤时间不足时的迟到提示。

默认的 `smart` 模式会逐段比较高德步行、公交和驾车方案，并在整天范围内优先选择不迟到、总耗时更短的组合。启用“有车出发”后，系统会持续记录车辆停放地点：驾车会把车带到目的地，改为步行或公交则把车留在原地，只有人重新回到停车点后才允许再次驾车。驾车段默认加入 10 分钟停车预留，可在页面调整；高德路线接口不保证实时车位，具体停车位仍需现场确认。

接口参数 `car_available` 表示出发时是否有车，`parking_minutes` 表示每次驾车抵达后的停车预留。仍可把 `mode` 指定为 `walking`、`transit` 或 `driving`，强制整天使用一种方式。

未配置 Web 服务 Key 时仍返回事项和点位，并使用直线作为视觉降级；未配置 JS API Key 时仍可查看左侧时间轴。

固定行程和任务也可以直接保存一次性 POI 的名称、城市和经纬度，不必把餐厅、车站出口等临时地点加入常用地点。Agent 在地点只有一个明确候选时会把搜索结果写入事项；存在多个合理候选时会先请求用户选择。

## 通勤约束排期

自动规划会在尝试任务时段时查询高德公交路线，并同时检查前一地点到任务、任务到下一固定行程是否可达。通勤时间不足的候选会被跳过，系统会继续寻找更合适的时段；整个规划范围都无法满足时，任务保持未安排并返回具体原因。

两个固定行程的时间都不能由规划器擅自修改，因此这类冲突会出现在规划分析和一日行程地图中，并明确显示预计迟到分钟数。未配置 Web 服务 Key 或地图临时不可用时，规划仍可完成，但分析会标记该次安排未完成通勤校验。

固定行程分为普通活动和赶路。普通活动的开始时间表示必须到达地点的时间；赶路行程的地点表示目的地，开始时间表示出发，结束时间表示最晚到达，并分别保存步行、公交/地铁、打车或自驾方式。打车与自驾都使用高德驾车路线，但只有自驾参与停车时间、取车路径和车辆位置连续性计算。生成前校验、创建后复查和行程地图共用这一方式，避免用公交耗时误判驾车路线，也避免把打车显示成自驾。这样“返回学校 19:10–20:15”会用 65 分钟赶路窗口与对应交通方式的高德耗时比较，不会在 19:10 前重复计算一次返校路线。

## Agent 工具

- `search_places`：地点不明确时搜索候选。
- `geocode_address`：解析明确地址。
- `estimate_travel_time`：根据坐标查询实际路线距离和耗时。

三项工具均为只读操作，不需要用户确认。Agent 被要求在地点存在歧义时先询问用户，并且不得自行编造距离和通勤时间。

## 扩展其它服务商

新增服务商只需实现 `app/integrations/maps/base.py` 中的 `MapProvider`，再在 `build_map_service()` 中按 `provider` 创建对应实现。HTTP 接口、Agent 工具和上层规划逻辑无需修改。
